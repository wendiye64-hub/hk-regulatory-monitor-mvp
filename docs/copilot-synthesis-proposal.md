# Copilot 模型综合接口方案（本次未实现）

目前只生成确定性总结：每个格子的后端 summary、结论标签、适用范围和条件；同一问题全部辖区完成后，逐个列出状态和依据位置。两个以上辖区都有通过全部机器校验的结论时，才对照结论标签的共同点或差异。所有机器通过结果仍待人工复核，不表示合规或违规。CSV Supplementary_Notes 的 Macro Synthesis 与页面使用同一个生成函数。

以后可增加 `POST /v1/research/synthesis`，输入仅包含同一问题已完成格子的 `export_record` 列表。每条记录带辖区和任务 ID；服务端核对记录与已保存任务一致，拒绝未完成、不同问题和客户端篡改的记录。不接受额外法规资料、检索结果或用户补充事实，不重新检索。

输出逐句结构：`sentences: [{ text, provenance: [{ jurisdiction, job_id, field_paths, evidence_ids, exact_quote }] }]`，另附 `validation_gates` 和 `publication_status`。每句话必须标注来源辖区，跨辖区句子必须分别标注各自出处。来源不足、失败或未校验的格子只能描述状态；实质比较至少需要两个通过校验的格子。

服务端逐一核对字段路径、原文摘录、证据 ID、引用链接和原格子校验状态，并独立校验句子是否超出记录支持范围。单纯存在正确引用不代表句子受到支持。任一句不通过则整个模型综合不显示，前端保留确定性总结并显示引用校验未通过；通过仍为 `review_pending`。前端也检查返回的状态，不能把模型文本直接覆盖确定性总结。

模型密钥只在后端本机环境变量。接口沿用 API Key、限流和审计，记录输入任务 ID、模型输出和每句校验结果。这次没有增加该接口或调用模型综合。
